# Merge Readiness

This branch turns ESO into a usable BTC-first lab for agent developers. The
merge should preserve code, tests, schemas, docs, benchmark specs, and curated
historical JSON artifacts. Generated report folders should stay untracked.

## What This Branch Adds

- Agent-facing CLI surfaces for `model-eval`, `benchmark`, `dissect`, and
  `dissect-many`.
- Causal target builders for future returns, direction, realized volatility,
  and volatility regimes.
- Supervised temporal baselines with manifest output and a model-run registry.
- Asset dissection bundles: feature/target correlations, quantile regimes,
  phase sectors, target summaries, and aggregate universe summaries.
- BTC reference-context features for alt analysis: relative returns, rolling
  correlation, rolling beta, and price-ratio z-scores.
- Versioned JSON contracts under `schemas/` and a lightweight validator.
- Agent handoff artifacts from `explore` so model builders can read assumptions
  before proposing architecture.

## Required Verification

Run this before merging:

```bash
python -m pytest -q
python -m eso.cli --help
python -m eso.cli model-eval --help
python -m eso.cli dissect --help
python -m eso.cli benchmark --help
```

For a self-contained smoke run without depending on private market data:

```bash
python -m eso.cli inspect examples/harmonic.csv --output reports/smoke_inspect.json
python -m eso.cli explore examples/harmonic.csv --output reports/smoke_explore --max-rows 500
python -m eso.cli validate-json reports/smoke_explore/report.json
python -m eso.cli validate-json reports/smoke_explore/artifacts/model_handoff.json
```

For the BTC lab path, when `data/BTCUSDT_1h.csv` exists locally:

```bash
python -m eso.cli dissect data/BTCUSDT_1h.csv \
  --asset-id BTCUSDT_1h \
  --feature-mode cycle \
  --horizons 3 12 \
  --train-size 15000 \
  --output reports/BTCUSDT_1h_dissect

python -m eso.cli benchmark benchmarks/btc_core.json --output reports/btc_core_benchmark
python -m eso.cli validate-json reports/BTCUSDT_1h_dissect/asset_dissect.json
python -m eso.cli validate-json reports/btc_core_benchmark/benchmark_result.json
```

## What To Stage

Use explicit paths so generated reports do not leak into the merge:

```bash
git add .gitignore README.md docs benchmarks schemas universes eso tests \
  experiments/10_direction_model_v2.py \
  reports/direction_model_v2/direction_v2_result.json
```

Root-level `BTC_RESEARCH_BRIEF.md` and `.md` are intentionally not listed here.
They existed as untracked local docs during this cleanup; include them only if
they are meant to become curated repo documentation.

## Generated Outputs

The repo now ignores generated ESO outputs:

```text
/reports/*
/experiments/eso_registry.csv
```

Tracked historical report JSONs remain tracked by Git. New benchmark,
dissection, smoke, and model-run outputs should be regenerated by commands,
not committed.

## Acceptance Criteria

- `python -m pytest -q` passes.
- CLI help lists `inspect`, `diagnose`, `explore`, `model-eval`, `model-runs`,
  `validate-json`, `benchmark`, `dissect`, and `dissect-many`.
- JSON artifacts validate through `python -m eso.cli validate-json`.
- New agents can start from `docs/agent_entry.md`, then use this file to check
  merge/test hygiene.
- BTC direction at 12h remains documented as a null result; do not let future
  agents present it as a validated edge without a manifest beating baseline.
